# Combat Lab — separate opt-in test build

This is a **test build**, not a finished Crystal Aura or AutoTotem. The normal Apollon build omits the Lab unless the build environment contains `ECLIENT_COMBAT_LAB=1`; `.github/workflows/combat-lab.yml` does that and creates `eclient-combat-lab-arm64`. Use the pinned 1.21.111 ARM64 APK and back up worlds before changing installations: debug signing keys are regenerated.

Combat > Combat Lab contains:

- **Arm one crystal attack (10s):** on the next eligible game tick, find the nearest existing actor with previously observed crystal type ID 71 within four blocks and call the existing Apollon attack wrapper once. No actor is retained across ticks. It cancels on panic/menu/death and expires after 10 seconds. `Attack attempted` means the function was called, not that a crystal broke. It does not place crystals, automatically target players, repeat attacks or implement Crystal Aura.
- **Transfer observation:** at startup this test build installs a passive hook on the matched `ContainerTransferClient` slot 3 target `0xcdc921c`, but only if the target's first 16 bytes equal the verified pinned-library prologue. When observation is started, the page counts calls and whether the first two arguments are non-null; logcat tag `EClientCombatLab` additionally logs up to 25 events and whether the third argument is nonzero. It does not read inventory bytes, retain raw pointers, call the function itself, equip a totem or prove an event was accepted. The hook is installed even while observation is stopped and cannot be uninstalled without restarting the game.

The transfer function is **inferred** from targeted Ghidra output as `void(self, input, third)`; its ABI, thread context and side effects are not validated. A hook can interfere with normal play, corrupt state or crash even when its prologue matches. No automatic inventory action is performed, because item identity, ownership and request semantics are unknown. This experiment tests whether manual operations reach the candidate and the old one-shot crystal path still works, not whether AutoTotem is complete. Test only in a backed-up disposable local world, not a valuable world or multiplayer server. A successful call/event is not proof of server acceptance; compare the actual inventory/crystal on screen. The page counter is process-local, no new Downloads log is created, and a crash may prevent updating it. Logcat can be collected separately if available.
